# 共有機能: COMEN01C

## 1. プログラムのエントリとコミュニケーションエリアの処理

呼び出し元プログラムとして、私はナビゲーションコントローラが入力されるセッションコンテキストを検証し、以前のナビゲーション状態を復元することで、以降の処理が一貫したベースラインを持つことを望む。

### 要件

REQ-F-001: [イベント駆動] プログラムが起動され、コミュニケーションエリアが存在しない場合（コミュニケーションエリアの長さがゼロの場合）、ナビゲーションコントローラは直ちにサインオン画面プログラムに制御を移さなければならない。

REQ-F-002: [イベント駆動] プログラムが起動され、コミュニケーションエリアの長さがゼロより大きい場合、ナビゲーションコントローラは入力されたコミュニケーションエリアをローカルコミュニケーションエリアレコードに復元し、発信元トランザクション識別子、発信元プログラム名、およびプログラムコンテキスト指標を保持しなければならない。

REQ-F-003: [遍在] ナビゲーションコントローラは、各起動の開始時にエラーフラグ指標をOFF状態にクリアし、メッセージテキストバッファをスペースで初期化しなければならない。

## 2. 初回起動と再入時の振り分け

メニュー利用者として、私は初回表示と再訪問をシステムが区別することで、毎回正しい画面状態が表示されることを望む。

### 要件

REQ-F-004: [イベント駆動] コミュニケーションエリアが存在し、プログラムコンテキスト指標が初回起動（再入ではない）を示す場合、ナビゲーションコントローラはクリアされた出力フィールドを持つメニュー画面を表示しなければならない。

REQ-F-005: [イベント駆動] コミュニケーションエリアが存在し、プログラムコンテキスト指標が再入を示す場合、ナビゲーションコントローラは利用者のメニュー画面入力を受信し、応答ステータスおよび理由コードを取得し、押下されたアテンション識別子に基づいて振り分けを行わなければならない。

REQ-F-006: [イベント駆動] 再入処理中にアテンション識別子がENTERキーの押下を示す場合、ナビゲーションコントローラはメニューオプション処理ハンドラへ経路制御を行わなければならない。

REQ-F-007: [イベント駆動] 再入処理中にアテンション識別子がPF3キーの押下を示す場合、ナビゲーションコントローラは遷移先プログラムをサインオン画面プログラムに設定し、それに制御を移さなければならない。

REQ-F-008: [イベント駆動] 再入時にENTERまたはPF3以外のキーが押下された場合、メニュー画面ハンドラは無効キーのエラーメッセージを表示し、メニュー画面を送信しなければならない。

## 3. メニューオプション入力の正規化と検証

メニュー利用者として、私は選択したオプションが遷移前に検証されることで、有効かつ権限のある選択のみが処理されることを望む。

### 要件

REQ-F-009: [遍在] メニューオプション入力正規化処理は、入力の末尾から末尾以外の非スペース文字まで逆方向に走査してメニューオプション入力の末尾のスペースを除去し、選択内容に残るスペースをゼロに置き換え、得られた英数字の値を数値形式に変換しなければならない。

REQ-F-010: [望ましくない] 正規化されたメニューオプションが数値でない、利用可能なメニューオプション数の上限である11を超える、またはゼロと等しい場合、メニューオプション検証処理はエラーフラグ指標を'Y'に設定し、「Please enter a valid option number...」というエラーメッセージをメッセージテキストに格納しなければならない。

REQ-F-011: [イベント駆動] 一般利用者が権限コードが'A'（管理者専用に制限）であるメニューオプションを選択した場合、メニュー権限強制処理はエラーフラグ指標を'Y'に設定し、「No access - Admin Only option... 」というエラーメッセージをメッセージテキストに格納し、メニュー画面を送信しなければならない。

## 4. メニューオプション遷移処理

メニュー利用者として、私は検証済みの選択が正しい遷移先プログラムへ私を導くことで、意図した機能に到達できることを望む。

### 要件

REQ-F-012: [複合] エラーフラグ指標が設定されておらず、かつ選択されたメニューオプションのプログラム名が'COPAUS0C'である間、プログラム遷移ハンドラは遷移先プログラムが利用可能であることを検証しなければならない。利用可能な場合、コミュニケーションエリアに発信元トランザクション識別子および発信元プログラム名を設定し、プログラムコンテキスト指標をゼロにリセットし、遷移先プログラムに制御を移さなければならない。遷移先プログラムが利用不可の場合、エラーメッセージの色を赤に設定し、そのオプションがインストールされていないことを示すエラーメッセージを表示しなければならない。

REQ-F-013: [複合] エラーフラグ指標が設定されておらず、かつ選択されたメニューオプションのプログラム名が'DUMMY'で始まる間、メニューオプションステータスハンドラはエラーメッセージの色を緑に設定し、「This option 」、メニューオプション表示名、および「is coming soon ...」を連結して構成される情報メッセージを表示しなければならない。

REQ-F-014: [複合] エラーフラグ指標が設定されておらず、かつ選択されたメニューオプションが標準オプション（'COPAUS0C'ではなく、'DUMMY'で始まらない）である間、メニューオプション処理プログラムはコミュニケーションエリアに発信元トランザクション識別子および発信元プログラム名を設定し、プログラムコンテキスト指標をゼロにリセットし、選択されたメニューオプションプログラムに制御を移さなければならない。

## 5. 遷移前の遷移先検証

呼び出し元プログラムとして、私はナビゲーションコントローラが常に有効な遷移先を確実に設定することで、制御が空の遷移先に渡されることが決してないことを望む。

### 要件

REQ-F-015: [状態駆動] プログラムが制御を移そうとしており、遷移先プログラム名が空または未初期化（LOW-VALUESまたはSPACESを含む）である場合、ナビゲーションコントローラは制御を移す前に遷移先プログラム名をサインオン画面プログラムに既定しなければならない。

REQ-F-016: [遍在] ナビゲーションコントローラは、最終処理としてコミュニケーションエリアに指定された遷移先プログラムに制御を移さなければならない。

## 6. メニュー画面表示

メニュー利用者として、私は現在のヘッダー情報とすべての利用可能なオプションでメニュー画面が完全に構成されることで、十分な情報に基づいた選択ができることを望む。

### 要件

REQ-F-017: [遍在] メニュー画面ヘッダー生成処理は、現在のシステム日時を取得し、画面タイトル行に'AWS Mainframe Modernization'および'CardDemo'を設定し、トランザクション識別子フィールドに'CM00'を、プログラム名フィールドに'COMEN01C'を設定し、現在日付をMM/DD/YY形式で書式化して表示し、現在時刻をHH:MM:SS形式で書式化して表示しなければならない。

REQ-F-018: [遍在] メニュー画面送信処理は、メニュー画面のヘッダー情報およびすべてのメニューオプション表示行を設定し、蓄積されたメッセージテキストをエラーメッセージ出力フィールドに移動し、表示前に画面をクリアするERASEオプション付きでメニュー画面を端末に送信しなければならない。

OQ-001: ルール7ad957eaおよび8bf90c8bはいずれも有効なメニューオプションの最大数を11としているが、ルール04a5424aでは組み立てループが11個のオプションまで反復すると記載されている。一方でルールc7c03249および32d5bdc1では12番目の出力位置が記述されている。12が有効な選択可能オプションであるのか、あるいは表示専用のスロットに過ぎないのかが不明確である。担当: ビジネス／プロダクトオーナー。

OQ-002: ルール32d5bdc1は、範囲外分岐がループカウンタの値1から12までの位置を対象とすると記載しており、これは12が定義済み位置の上限であることを示唆している。しかし、検証ルールでは選択可能なオプションを11に制限している。位置12が通常運用中に設定されることがあるのか、また選択可能であるのかについて明確化が必要である。担当: ビジネス／プロダクトオーナー。

OQ-003: ルール31f64527およびfc55f924はいずれも、プログラム利用可能性チェックを伴う'COPAUS0C'への遷移経路を記述している。この利用可能性チェックが'COPAUS0C'にのみ適用されるのか、あるいはルール1bae53bdで対象とされる標準オプションにも必要とされるのかが不明確である。担当: ビジネス／プロダクトオーナー。
